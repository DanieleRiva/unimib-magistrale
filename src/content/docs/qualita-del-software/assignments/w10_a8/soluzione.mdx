## La traccia in breve

L'obiettivo dell'assignment era eseguire manualmente il lavoro di un motore di **Symbolic Execution**. 
Dato il metodo `m(int x, int y)`, dovevamo tracciare tutti i possibili cammini, aggiornando a ogni passo lo **Symbolic State** e calcolando la **Path Condition (PC)** per le biforcazioni degli `if`.

Il codice da analizzare, annotato con i nodi, era:

```java
public int m(int x, int y) {
    if (y > 0) {       // Nodo 1
        y = y - x;     // Nodo 2
        if (y < 0) {   // Nodo 3
            x = x + y; // Nodo 4
        }
    }
    if (x > y) {       // Nodo 5
        x = x - y;     // Nodo 6
    }
    return x;          // Nodo 7
}
```

## Il "Mistero" del 9/10: Dimostrazione dell'Infeasible Path

Nella tabella excel, riga 7, ho tracciato il cammino `1T -> 2 -> 3T -> 4 -> 5F -> 7`. Ho scritto la PC finale: `Y > 0 AND Y - X < 0 AND Y <= Y - X`. 

**La domanda fatidica: Perché questo cammino mi è costato 1 punto?**
Perché l'esecuzione simbolica non fa solo "copia-incolla" di equazioni, ma tramite l'SMT Solver ne valuta la **Soddisfacibilità**. 

Se all'orale mi chiedono di dimostrare l'errore alla lavagna, farò questa dimostrazione algebrica partendo dalla PC di quella riga:
1. Analizzo l'ultima disuguaglianza: `Y <= Y - X`.
2. Sottraendo `Y` da entrambi i lati ottengo `0 <= -X`, che invertita significa `X <= 0`.
3. Analizzo la disuguaglianza centrale: `Y - X < 0`. Spostando la X ottengo `Y < X`.
4. Mettendo a sistema i due risultati: `Y < X` ma `X <= 0`. Proprietà transitiva: `Y` deve essere per forza minore di `0`.
5. Ora guardo la primissima condizione della PC: `Y > 0`.

Conclusione: Ho scritto un cammino che richiede `Y > 0 AND Y < 0`. È una contraddizione matematica (`UNSAT`). Questo cammino è un **Infeasible Path**. Non avrei dovuto scriverlo come cammino finale, ma avrei dovuto annotare la riga con "UNSAT" e fermare l'esplorazione, esattamente come fa un motore simbolico reale quando "pota" un albero (Pruning).

## Analisi riga per riga: Come calcolare lo Stato Simbolico (Cammino T-T-T)

Per dimostrare di saper eseguire la **Sostituzione all'indietro (Back-substitution)**, vediamo esattamente come si compilano le celle dell'Excel per il cammino più complesso: Tutto Vero (`1T -> 2 -> 3T -> 4 -> 5T -> 6 -> 7`).

1. **Stato iniziale:** - `x = X`, `y = Y`. La PC è `true`.

2. **Nodo 1 (`if y > 0` - VERO):**
   - La variabile `y` nello stato simbolico vale `Y`. Sostituisco.
   - Nuova PC: `Y > 0`.

3. **Nodo 2 (`y = y - x`):**
   - Valuto l'espressione a destra leggendo lo stato attuale: `y` vale `Y`, `x` vale `X`. 
   - Il risultato algebrico è `Y - X`.
   - Aggiorno lo stato simbolico: ora `y = Y - X`. `x` rimane `X`.

4. **Nodo 3 (`if y < 0` - VERO):**
   - Qual è il valore simbolico di `y` in questo momento? È `Y - X`. Sostituisco.
   - La condizione valutata diventa `Y - X < 0`.
   - Aggiorno la PC con un AND: `Y > 0 AND Y - X < 0`.

5. **Nodo 4 (`x = x + y`):**
   - **Attenzione qui!** Valuto l'espressione a destra leggendo lo stato attuale. `x` vale `X`. Ma `y` ora vale `Y - X`.
   - L'espressione matematica diventa: `X + (Y - X)`.
   - Le due `X` si annullano! Il risultato è `Y`.
   - Aggiorno lo stato simbolico di `x`. Ora `x = Y`.

6. **Nodo 5 (`if x > y` - VERO):**
   - Sostituisco con i valori attuali. `x` vale `Y`. `y` vale `Y - X`.
   - La condizione valutata è: `Y > Y - X`.
   - Semplificando l'espressione, tolgo `Y` e inverto i segni: ottengo `X > 0`.
   - Aggiorno la PC: `Y > 0 AND Y - X < 0 AND X > 0`.

7. **Nodo 6 (`x = x - y`):**
   - Valuto l'espressione. `x` vale `Y`. `y` vale `Y - X`.
   - L'espressione diventa: `Y - (Y - X)`. Risolta, togliendo le parentesi: `Y - Y + X`, che fa `X`.
   - Aggiorno lo stato simbolico di `x`. Ora `x = X`. Sorprendentemente, dopo tutti questi calcoli, `x` è tornata al suo valore originale.

8. **Nodo 7 (`return x`):**
   - Il programma ritorna il valore di `x`. Leggo lo stato simbolico di `x` che attualmente è `X`. 
   - Output del programma: `X`.

## Domande di difesa probabili (Roleplay)

1. **Professore:** "Al Nodo 4, nel suo stato simbolico per la variabile `x`, lei ha scritto semplicemente `Y`. Come c'è arrivato partendo dall'istruzione `x = x + y`?"
   **Risposta:** "Tramite la sostituzione all'indietro (*back-substitution*). L'istruzione va valutata leggendo l'istantanea dello stato simbolico in quel preciso momento. Al Nodo 2 la variabile `y` era stata sovrascritta con la formula `Y - X`. Quindi, l'espressione `x + y` matematicamente diventa `X + (Y - X)`. Svolgendo l'equazione algebrica, le due X si eliminano, lasciando la `x` puramente uguale a `Y`."

2. **Professore:** "A cosa serve l'operazione di semplificazione (es. trasformare `Y > Y - X` in `X > 0`) all'interno della Path Condition? Potevamo tenerla non semplificata?"
   **Risposta:** "In linea teorica sì, per un SMT Solver moderno non fa alcuna differenza ricevere la formula lunga o quella semplificata, la risolverebbe comunque. Tuttavia, per l'analisi umana, semplificare le disequazioni è fondamentale per accorgersi a colpo d'occhio delle contraddizioni matematiche e individuare tempestivamente gli *Infeasible Paths* prima ancora di passarli al Solver."
